# Hitbox ESP

Клієнтський розширювач хітбоксів і ESP для Roblox: один файл Luau з компактним
інтерфейсом.

[English](README.md) · **Українська**

> [!WARNING]
> Скрипт змінює об'єкти **лише на вашому клієнті**. Він не впливає на серверну
> реєстрацію попадань, шкоду чи фізику. Використання в грі може порушувати
> правила цієї гри або Умови використання Roblox і призвести до модерації чи
> бану акаунта. Використовуйте на свій ризик, бажано на приватному сервері.
> Автори не надають жодних гарантій.

## Можливості

- **Розширення хітбоксів** — змінює розмір частин персонажів усіх інших гравців
  на вашому клієнті, розмір від 1 до 50 studs.
- **ESP** — ім'я, display name, відстань у studs і здоров'я, а також `Highlight`
  у кольорі команди. Підписи й підсвічування оновлюються з частотою 10 Гц.
- **Точне відновлення** — кожна змінена властивість (`Size`, `Transparency`,
  `CanCollide`, `Color`, `Material`, `CastShadow`) зберігається для кожного
  персонажа і відновлюється після вимкнення, респавну або закриття скрипта.
- **Зручний GUI** — темна/світла тема, згортання, перетягування вікна з
  обмеженням, панель налаштувань, підтвердження перед закриттям.
- **Збереження налаштувань** — розмір, тема, хоткеї, перемикачі та позиція вікна
  зберігаються між сесіями, якщо екзекутор підтримує файловий API.
- **П'ять хоткеїв** — перемикання хітбоксів, ESP, GUI, згортання та застосування
  розміру. Конфлікти клавіш вирішуються автоматично.
- **Безпечний життєвий цикл** — закриття вивантажує все (з'єднання, цикл, GUI,
  підсвічування), а повторний запуск замінює попередній екземпляр, а не додає
  другий.

## Вимоги

| Вимога | Примітка |
| --- | --- |
| Клієнт Roblox з Luau-екзекутором | Скрипт працює локально і не звертається до серверів. |
| Підтримка `Highlight` | Додано в Roblox у 2021 році; є в будь-якому актуальному клієнті. |
| `writefile` / `readfile` / `isfile` | Необов'язково. Без них GUI працює, але показує `Persistence: unavailable`. |
| Класичний риг R6 або R15 | Частини шукаються за назвою (`HumanoidRootPart`, `Head`, `UpperTorso`, …). Кастомні риги з перейменованими частинами не підтримуються. |

## Встановлення

Скопіюйте [`HitboxEsp.luau`](HitboxEsp.luau) в екзекутор і запустіть, або:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/romokaso/Hitbox-expander-and-esp/main/HitboxEsp.luau"))()
```

Вікно відкривається по центру екрана. Закриття через GUI відновлює всі хітбокси
та видаляє всі об'єкти ESP.

## Використання

| Елемент | Дія |
| --- | --- |
| **Hitbox size** + **Apply** | Задає масштаб частин. Значення обмежуються 1–50 і округлюються до десятих. <kbd>Enter</kbd> у полі також застосовує значення. |
| **Hitbox: ON/OFF** | Розширює або відновлює хітбокси всіх інших гравців. |
| **ESP: ON/OFF** | Додає або прибирає підписи (ім'я, відстань, здоров'я) і підсвічування. |
| **⚙** | Налаштування: тема, приховування частин, відновлення при старті, хоткеї, скидання позиції. |
| **_** | Згортає до заголовка. |
| **X** | Питає підтвердження і вивантажує скрипт. |

### Хоткеї

Спочатку всі хоткеї не призначені. Щоб призначити:

1. Відкрийте **Settings**.
2. Натисніть кнопку навпроти дії.
3. Натисніть потрібну клавішу.

- <kbd>Backspace</kbd> або <kbd>Delete</kbd> очищає прив'язку.
- <kbd>Escape</kbd> скасовує очікування клавіші.
- Одна клавіша належить лише одній дії: призначення зайнятої клавіші переносить
  її на нову дію.
- Прив'язки ігноруються, коли клавішу споживає гра (чат, меню) або коли
  фокус у текстовому полі.
- Прив'язки працюють і при прихованому GUI — так можна повернути інтерфейс,
  якщо ви прив'язали перемикання GUI.

### Налаштування та файли

Файли лежать у робочій області екзекутора:

| Файл | Призначення |
| --- | --- |
| `hitbox_esp_settings.json` | Поточні налаштування (версія схеми 2). |
| `hitbox_esp_settings.json.bak` | Попередні коректні налаштування, оновлюються при кожному збереженні. |
| `hitbox_esp_settings.json.corrupt` | Копія файлу, який не вдалося розібрати, для діагностики. |

Кожне значення перевіряється й обмежується при завантаженні. Пошкоджений або
відредагований вручну файл не ламає запуск: використовуються типові значення або
резервна копія.

**Restore on start** знову вмикає збережені перемикачі Hitbox/ESP при наступному
запуску. Типово вимкнено, щоб нова сесія не починала розширювати хітбокси сама.

## Підтримка ригів

- R6: `HumanoidRootPart`, `Head`, `Torso`, `Left Arm`, `Right Arm`, `Left Leg`,
  `Right Leg`.
- R15: `HumanoidRootPart`, `Head`, `UpperTorso`, `LowerTorso`,
  `LeftUpperArm`, `LeftLowerArm`, `LeftHand`, `RightUpperArm`, … (усі 15 частин).

Частини шукаються за назвою, змінюються лише прямі дочірні елементи моделі
персонажа, відсутні частини пропускаються. Скіннені меші, кастомні риги та
аксесуари не змінюються.

## Розробка

```bash
stylua .                    # форматування (StyLua 2.x)
lua5.4 tests/run.lua        # юніт-тести чистих функцій
lua5.4 tests/smoke.lua      # наскрізні тести на моку Roblox API
```

Roblox для запуску тестів не потрібен. `docs/ci-workflow.yml` містить готовий
GitHub Actions workflow, який запускає обидва набори на Lua 5.4 і перевіряє
форматування StyLua; скопіюйте його в `.github/workflows/ci.yml`, щоб увімкнути.

### Структура проєкту

```
HitboxEsp.luau            скрипт (один файл з нумерованими секціями)
tests/run.lua             юніт-тести чистих функцій
tests/smoke.lua           наскрізні тести (GUI, перемикачі, ESP, збереження, unload)
tests/mock_roblox.lua     мінімальний мок Roblox API для smoke-тестів
docs/ci-workflow.yml      готовий CI workflow (тести + форматування)
```

### Редагування скрипта

`HitboxEsp.luau` поділений на пронумеровані секції. Блок між
`-- >>> PURE BEGIN` і `-- <<< PURE END` не повинен звертатися до Roblox API:
юніт-тести завантажують саме цей блок, і окремий тест падає, якщо в ньому
з'являться `game`, `Instance`, `Enum`, `task` тощо.

Smoke-тести запускають весь файл на `tests/mock_roblox.lua`, який реалізує
потрібні частини Roblox API: інстанси та `Parent`, сигнали, твіни, планувальник
`task`, файлову систему в пам'яті та невеликий JSON-кодек. Якщо додаєте новий
Roblox API, розширте мок у тому ж коміті.

### Оновлення версії

1. Змініть `SCRIPT_VERSION` у `HitboxEsp.luau`.
2. Додайте запис у [`CHANGELOG.md`](CHANGELOG.md).
3. Поставте тег релізу (`v2.0.0`), щоб можна було зафіксувати перевірену версію.

## Проблеми та рішення

| Симптом | Причина / рішення |
| --- | --- |
| Налаштування не зберігаються | В екзекутора немає файлового API. Панель показує `Persistence: unavailable`. |
| Налаштування скидаються після ручного редагування | Файл має бути JSON-об'єктом. Некоректний файл копіюється в `.corrupt`, далі використовуються типові значення або резервна копія. |
| Вікно за межами екрана | Перетягування завжди лишає 120 px видимими, збережена позиція обмежується при старті, а **Settings → Reset position** центрує вікно. |
| Нічого не змінюється на кастомному ризі | Частини шукаються за назвою; перейменовані або скінені частини пропускаються. |
| Два вікна після повторного запуску | Другий запуск просить перший екземпляр вивантажитися і прибирає старий GUI. Якщо запущена стара версія скрипта, перезайдіть на сервер. |
| Немає підписів ESP | У клієнті немає підтримки `Highlight`/`BillboardGui` або гравець мертвий. |
